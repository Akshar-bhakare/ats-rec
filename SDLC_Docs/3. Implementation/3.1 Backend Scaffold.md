## **B. MetaDB Connection (Singleton)**

**Purpose:**
One global MongoDB connection for `MetaDB` (holds tenants, config, UltraAdmins).

**Setup Example:**

```typescript
// meta.module.ts
@Module({
  imports: [
    MongooseModule.forRoot(process.env.META_DB_URI, { connectionName: 'meta' }),
    MongooseModule.forFeature([{ name: 'Tenant', schema: TenantSchema }], 'meta')
  ],
  providers: [MetaService],
  exports: [MetaService]
})
export class MetaModule {}
```

## **C. Dynamic Tenant DB Connection**

**Purpose:**
Every request uses correct tenant DB, resolved by subdomain/JWT/header (see your Tenant Middleware plan).

**Key Approach:**

* Use NestJS [Request-scoped providers](https://docs.nestjs.com/fundamentals/injection-scopes#request-provider) or [nestjs-mongoose-tenant](https://github.com/kkratz/nestjs-mongoose-tenant) pattern.
* Connection pool per tenant DB URI, cache after first connect.

**Sample Middleware:**

```typescript
// tenant.middleware.ts
@Injectable()
export class TenantMiddleware implements NestMiddleware {
  constructor(private metaService: MetaService, private tenantService: TenantService) {}

  async use(req: Request, res: Response, next: NextFunction) {
    const tenantCode = extractTenantCode(req); // from subdomain, JWT, or header
    const tenant = await this.metaService.findTenantByCode(tenantCode);
    if (!tenant) return res.status(403).send('Tenant not found');
    req['tenant'] = tenant;

    // Set up dynamic connection
    await this.tenantService.setTenantConnection(tenant.db_uri);
    next();
  }
}
```

**TenantService Example:**

```typescript
@Injectable()
export class TenantService {
  private connections = new Map<string, Connection>();
  async setTenantConnection(dbUri: string): Promise<void> {
    if (!this.connections.has(dbUri)) {
      const conn = await mongoose.createConnection(dbUri, { /* options */ });
      this.connections.set(dbUri, conn);
    }
    // Optionally: set context for request
  }
  getConnection(dbUri: string): Connection {
    return this.connections.get(dbUri);
  }
}
```

## **D. Core Module Structure**

* **Meta Module**: CRUD for tenants, global admins, global config.

* **Auth Module**: JWT login, RBAC, invite flow.

* **Tenant Modules**:

  * **Users Module:** Per-tenant user CRUD, roles (Recruiter, ClientAdmin, Agency, Candidate, Interviewer)
  * **Jobs Module:** Per-tenant job CRUD, pipeline, search
  * **Candidates Module:** Candidate CRUD, resume upload
  * **Interviews Module:** Interview scheduling, reschedule, feedback, panelist assignment
  * **Agencies Module:** CRUD, assignments, dashboard
  * **Feedback Module:** Panelist feedback, link to interviews
  * **Audit Module:** Per-tenant action logging

* **AI/Call/WebSocket Modules**: Plivo, STT/TTS, OpenAI orchestration.

* **Notifications Module:** Email/SMS/WhatsApp.

* **Files Module:** Resume/avatar upload, S3 integration.

## **E. Config and Environment**

* `.env` at root:

  * `META_DB_URI`
  * `JWT_SECRET`
  * `S3_BUCKET`, etc.

* Use [@nestjs/config](https://docs.nestjs.com/techniques/configuration) for environment management.

## **F. First Run**

1. **Install:**
   `cd backend && npm install`
2. **Env:**
   Copy `.env.example` to `.env`, fill values.
3. **Dev Start:**
   `npm run start:dev`
4. **Lint/Test:**
   `npm run lint && npm test`
