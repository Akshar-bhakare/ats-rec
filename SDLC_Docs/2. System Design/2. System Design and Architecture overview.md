```plaintext
+----------------------------+               |      |   |   |   |   |  |

      V           V                          V      V   V   V   V   V  |
+-----------------+  +---------------------+   +-------------------+   +-------------------+
| MongoDB         |  | Object Storage      |   |  Redis/BullMQ      |   |  3rd-Party APIs   |
| - MetaDB        |  | (Resumes, Avatars)  |   |  (Job Queue)       |   |  (Plivo, Google,  |
| - Tenant DBs    |  |                     |   |                   |   |   OpenAI, Twilio) |
+-----------------+  +---------------------+   +-------------------+   +-------------------+
```

**Notes:**

* **MetaDB** holds tenants, cross-tenant admin, global config.
* **Tenant DBs**: Each client/agency gets a separate DB (hard isolation).
* **Backend API**: Every request passes through a tenant resolver (middleware), enforcing isolation.
* **WebSocket Server**: Handles real-time media for Plivo/AI, orchestrates Google STT/TTS and OpenAI API.
* **Job Queue**: For async tasks (AI processing, notifications, bulk imports).
* **Object Storage**: File uploads (resumes, avatars).
* **External APIs**: All 3rd-party calls centralized and monitored.
* **Frontend**: Auth-aware, role-driven; connects to backend, status, and media events.

## **D. Interactions & Data Flows (Examples)**

* **Interviewer receives invite:**
  → Backend generates one-time invite, sends via Email/SMS
  → Interviewer logs in, dashboard shows all assigned interviews
  → Can view, reschedule, join, and submit feedback (limited to assigned interviews)

* **Recruiter/ClientAdmin schedules interview:**
  → Schedules, assigns panelist(s), candidate
  → Invites Interviewer(s) by email
  → Dashboard updates for all parties

* **AI Call/Interview flow:**
  → Recruiter starts campaign
  → Backend queues job, triggers WebSocket/Plivo
  → Media streamed, audio sent to Google STT
  → Text to OpenAI, AI response synthesized via TTS
  → Audio returned to Plivo, candidate hears/answers
  → Results saved, recruiter notified

## **E. Security & Observability**

* **Hard tenant isolation** (enforced in backend and DB layer)
* **All data encrypted** in transit (TLS) and at rest (MongoDB)
* **RBAC everywhere**—no cross-role or cross-tenant data leakage
* **Audit logs and compliance hooks** in all sensitive flows
* **Central error monitoring, tracing, alerts**

## **F. DevOps & Monitoring**

* **Dockerized** services (frontend, backend, workers, WebSocket)
* **CI/CD** (GitHub Actions or similar) with automated build, test, deploy
* **Monitoring:** Prometheus/Grafana for metrics, Sentry for errors, alerting for downtime/errors/latency
