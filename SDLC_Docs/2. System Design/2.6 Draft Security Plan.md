# **Security Plan**

---

## **A. Authentication**

| Aspect              | Approach                                                              |
| ------------------- | --------------------------------------------------------------------- |
| **Login**           | Email/password + optional OTP/2FA for all users                       |
| **Password Policy** | Min 8 chars, upper/lower/number/special; reset link expires in 15 min |
| **Invite Flow**     | Only Admins can invite users; invite via email, with one-time token   |
| **JWT**             | All APIs secured by signed JWT tokens (short expiry, refresh token)   |
| **SSO** (optional)  | Support SAML/OAuth for enterprise tenants if required                 |

---

## **B. Role-Based Access Control (RBAC)**

| Level                    | Notes                                                               |
| ------------------------ | ------------------------------------------------------------------- |
| **Roles**                | UltraAdmin, ClientAdmin, Recruiter, Agency, Candidate, Interviewer  |
| **Permissions**          | CRUD and workflow actions mapped to roles                           |
| **Enforcement**          | RBAC guard/middleware on every endpoint, validated at service layer |
| **Tenant Scope**         | All actions constrained to data from current tenant context         |
| **Panelist/Interviewer** | Can only access interviews assigned to them                         |

---

## **C. Tenant Isolation**

| Technique              | Implementation Details                                                        |
| ---------------------- | ----------------------------------------------------------------------------- |
| **Data Isolation**     | Each tenant has separate MongoDB database URI; all queries are per-tenant DB  |
| **Context Injection**  | Middleware injects tenant context from subdomain/JWT/header for every request |
| **Access Restriction** | Never query across tenants in any service or background job                   |
| **API Exposure**       | Never expose tenant code in client-modifiable fields (subdomain/JWT only)     |
| **Audit Logging**      | All access, especially cross-tenant attempts, is logged with IP/user/context  |

---

## **D. Encryption**

| Data/Channel | Encryption Standard                         |
| ------------ | ------------------------------------------- |
| In Transit   | TLS 1.2+ enforced on all endpoints          |
| At Rest      | MongoDB “encrypted storage engine” enabled  |
| Backups      | Stored in encrypted (AES256/SSE) buckets    |
| JWT Secrets  | Kept in platform-provided secrets store     |
| Credentials  | All secrets managed via Railway/Vercel/etc. |

---

## **E. Data Privacy & Compliance**

* **User consent required** for recording/transcription of interviews (GDPR/IT Act).
* **Right to Erasure:** Candidate or client can request deletion; flagged and purged after validation.
* **Audit logs** retained per compliance window (e.g., 1 year).
* **Data access logs** exportable on admin request.

---

## **F. Secure Development Practices**

* **Static code analysis:** Linting, dependency CVE scans on every build.
* **Secret scanning:** No secrets in code or Git, enforced by pre-commit and pipeline tools.
* **Input validation:** All user input validated/sanitized (server + client side).
* **Rate limiting:** API endpoints protected from brute force/DOS (e.g., express-rate-limit/NestJS guard).
* **CORS policy:** Allowed origins tightly scoped per environment.

---

## **G. Operational Security**

* **Least privilege:** Only necessary permissions on DB/storage/API for services.
* **Rotation:** API keys, JWT secrets, and DB passwords rotated every 90 days or after incident.
* **Alerting:** Admins notified on suspicious activity (multiple failed logins, access outside normal hours, etc).
* **Emergency controls:** UltraAdmin “pause tenant” and “maintenance mode” available.

---

## **H. Vulnerability & Patch Management**

* **Dependencies:** Weekly review and auto-PRs for NPM security patches.
* **Penetration Testing:** Scheduled pre-launch and after major changes.
* **Incident Response:** Runbook for breaches; notification policy for clients.
